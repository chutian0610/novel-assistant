# 一致性以结构化事实库为主，检索为辅；V1 不上向量库

长篇一致性的业界教训：AI_NovelGenerator 作者实测纯向量检索"没有时间关系，分不清前后顺序，后期反而造成剧情混乱"，最终改回结构化库 + AI 自主查询（见 docs/research/ai-novel-landscape.md）。我们决定：一致性数据（角色运行时/关系/时间轴/伏笔账本）存 SQLite 结构化表，每条事实带来源章与原文证据供审计；检索层用 FTS5/BM25 起步，所有检索结果按章节号重排后再注入；向量检索等素材库规模真实变大后按需再加。

## Consequences

- 事实的正确形态是"带时序的行"，不是"语义相似的点"
- 未来引入 embedding 只能作为检索排序的增强，不能成为一致性的数据源
